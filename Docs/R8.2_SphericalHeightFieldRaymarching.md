# R8.2：Spherical Height Field Ray Marching（球面高度场光线步进）

> 本文档是 [R8_ParametricTint.md](R8_ParametricTint.md) 的子里程碑增量稿（R8.2 子里程碑），独立成稿是因为 R8 主稿已经超过 130 KB，再追加约 +500 行的 SHFRM 内容会过度膨胀。R8.0 baseline + R8.1 多通道增量留在主稿；R8.2 微观地表位移在本稿落地。
>
> **R8.2 一句话目标**：在 R8.1 已经接通的 BaseColor + Normal + Roughness 三通道之上，**激活 `PBRBaseHeight` 资产做球面高度场光线步进**（SHFRM，Spherical Height Field Ray Marching），让球面在材质域产生**真实的厘米级地表位移**——能看到山脉剪影从球轮廓凸出、山脉自阴影、视线穿过山谷的视差，而不是 POM 那样的"切线空间假视差"。
>
> **拍板时间**：2026-06-30。**前置依赖**：R8.0 ✅ + R8.1 ✅。**与 W4 / T 阶段的关系**：与 R8.0/R8.1 同——本稿不消费 W4 输出（仍用 Knuth 哈希 placeholder 的 17 配方）；T 阶段宏观地形位移与 SHFRM 微观位移在量纲上正交（T = 公里级，SHFRM = 厘米级），无需互改。

## 0. 一句话目标 + 与 POM 的本质差异

### 0.0 SHFRM 究竟做了什么

R8.1 的 Triplanar 三件套（Albedo/Normal/Roughness）虽然让球面有了**纹理凹凸感**，但所有像素的世界坐标 `WorldPos` **始终在原始光滑球面上**——球的几何轮廓还是一个完美球。换句话说：用户从地面以低角度看远方山脉时，看不到山脉从球边凸出来。

SHFRM 把这件事彻底改变：每个像素从相机出发沿真实视线进入球体，**沿视线 raymarch 找"地表的真实交点"**——交点的世界坐标就是该像素真正应该渲染的位置。最终的 BaseColor / Normal / Roughness 在这个交点上重新算（仍走 R8.1 的 `SAMPLE_PARAM_PBR` 宏），同时通过 `PixelDepthOffset` 把真实交点深度写回 ZBuffer，使 SSAO / SSR / Lumen 都能正确响应这个新表面。

### 0.1 SHFRM vs POM（Parallax Occlusion Mapping）

| 维度 | POM | **SHFRM** |
| --- | --- | --- |
| 视差空间 | 切线空间 2D UV 偏移 | **世界空间 3D 真位移** |
| 山脉从球轮廓凸出 | ❌（仅切平面错位）| **✅**（真位移到球外，silhouette 改变）|
| 山脉自阴影（视线被前山遮挡）| ❌ | **✅**（raymarch 自然解决）|
| 视线穿过山谷的视差感 | 部分 | **✅**（视线沿真路径前进）|
| 像素深度（ZBuffer）| 仍是球面 ⚠ | **真实位移面**（`PixelDepthOffset`） |
| 与 Lumen / SSAO / SSR 兼容性 | 部分 | **完美**（写出真深度后下游全部正确响应）|
| 与 Triplanar 框架的耦合 | 复杂（轴切换裂缝问题）| **天然适配**（每步只算一组 dir，无轴切换）|
| GPU 成本（3060, 1080p）| ~5~6 ms（B' 三轴 vector blend）| **~4~5 ms** |

**意外结果**：SHFRM 比 POM 更便宜——根本原因是 POM 需要"每个 cell 都重算 PBR 三件套"（3 cell × 27 次采样 = 81 次），而 SHFRM 命中后**只在 hit point 上算 1 次三件套**（27 次采样）。

## 1. 几何与数学

### 1.1 球面高度场的形式化定义

设：
- $\mathbf{C}$：球心（`PlanetCenter`，MID Vector 参数）
- $R$：球面半径（cm，几何域已存在的 mesh 半径）
- $\hat{\mathbf{u}}$：球面方向，$\hat{\mathbf{u}} = (\mathbf{P} - \mathbf{C}) / |\mathbf{P} - \mathbf{C}|$
- $H_\text{tex}(\hat{\mathbf{u}}) \in [0, 1]$：高度场纹理（`PBRBaseHeight` Triplanar 采样后的灰度值）
- $h_\text{cell}(\hat{\mathbf{u}})$：当前 cell 配方的 `HeightScaleCM` 字段（cm，0~50）

**球面高度场表面**：

$$
S(\hat{\mathbf{u}}) \;=\; \mathbf{C} + \hat{\mathbf{u}} \cdot \bigl(R + H_\text{tex}(\hat{\mathbf{u}}) \cdot h_\text{cell}(\hat{\mathbf{u}})\bigr)
$$

即：球面上每一点沿径向被推出 `H_tex × HeightScaleCM` 的距离。

### 1.2 视线与高度场的求交问题

给定相机位置 $\mathbf{O}_\text{cam}$ 与该像素的视线方向 $\hat{\mathbf{v}}$（指向像素），求最近交点 $\mathbf{P}_\text{hit}$ 满足：

$$
|\mathbf{P}_\text{hit} - \mathbf{C}| \;=\; R + H_\text{tex}(\hat{\mathbf{u}}_\text{hit}) \cdot h_\text{cell}(\hat{\mathbf{u}}_\text{hit})
$$

其中 $\hat{\mathbf{u}}_\text{hit} = (\mathbf{P}_\text{hit} - \mathbf{C}) / |\mathbf{P}_\text{hit} - \mathbf{C}|$。

这是一个隐函数方程，无闭式解。SHFRM 用线性 raymarch + secant refine 数值求解。

### 1.3 raymarch 起点优化

PS 阶段每个像素的 `WorldPos` 即原始光滑球面 mesh 的世界坐标，**它已经在球面上**（由 VS 灌的几何决定）。所以 raymarch 起点直接用 `WorldPos`，不需要重新算"视线与球的入射交点"——这一点比一般 sphere tracing 方案省了一次 ray-sphere intersection。

**但**：`WorldPos` 仅是高度场的**球面 baseline**——它当前位于 $|P - C| = R$ 上。如果该像素对应的高度场 $H_\text{tex} > 0$，则真实地表 $|P_\text{hit} - C| > R$，地表在 baseline **之上**——视线先碰到的是"凸出来的山"。

所以 SHFRM 的 raymarch **从 P0 = WorldPos 出发，沿视线反方向（即朝相机方向）走** —— 直到 raymarch 路径穿过当前位置径向高度等于 `H_tex × HeightScaleCM` 的曲面（命中地表）。**这是 SHFRM 与传统 POM 最反直觉的一步**：步进方向是**朝向相机**而不是远离。

> **直觉解释**：球面 mesh 是高度场的 "下界" baseline——所有山脉位移都在这条 baseline 之**上**（径向更远离球心）。从相机看，要先看到山脉就要从 mesh 表面**往相机方向退**。

### 1.4 raymarch 步进公式

参数化视线：

$$
\mathbf{P}(t) \;=\; \mathbf{P}_0 + (-\hat{\mathbf{v}}) \cdot t \cdot D_\max,\quad t \in [0, 1]
$$

其中 $D_\max$ 是 raymarch 最大深度（沿视线长度，cm）。`MaxRaymarchDepthCM` 取 `max(HeightScaleCM_global) × 1.5`，默认 75 cm（保险冗余）。

每步算：
- 当前点的径向高度：$h_\text{radial}(t) = |\mathbf{P}(t) - \mathbf{C}| - R$
- 当前点对应方向上的高度场：$h_\text{field}(t) = H_\text{tex}(\hat{\mathbf{u}}(t)) \cdot h_\text{cell}$
- 命中条件：$h_\text{radial}(t) > h_\text{field}(t)$（视线超过了地表高度）

**初始 $t = 0$ 时**：$P(0) = P_0 = $ WorldPos，正好在球面 baseline 上 → $h_\text{radial}(0) = 0 \le h_\text{field}(0)$（除非 $h_\text{field} = 0$，此时已经在地表，无需 raymarch）。**raymarch 从地表内部开始向上找出口**——这是 SHFRM 的本质。

## 2. HLSL 实现

### 2.1 PBRBaseHeight Triplanar 采样宏

R8.2 新增 `SAMPLE_HEIGHT_FIELD` 宏，专门用于 raymarch 中每一步的 height 采样：

```hlsl
// ---------- Macro: PBRBaseHeight Triplanar 采样（R8.2 新增）----------
//   DIR_       : float3，球面方向 (P - PlanetCenter) / |P - PlanetCenter|
//   WP         : float3，世界坐标
//   BASE_TILE  : float，TileScale（与 SAMPLE_PARAM_PBR 同款）
//   BASE_IDX   : int，BaseTexIdx（来自 dominant cell 的 LUT0.r）
//   TRI_MUL    : float，TriplanarScale 修正（来自 dominant cell 的 LUT3.a）
//   OUT_H      : float（外部已声明），高度场灰度值 [0, 1]（取 .g 通道，与 Roughness 同款）
#define SAMPLE_HEIGHT_FIELD(DIR_, WP, BASE_TILE, BASE_IDX, TRI_MUL, OUT_H)               \
{                                                                                        \
    float3 _absN = pow(abs((DIR_)), TriplanarSharpness);                                 \
    _absN /= dot(_absN, float3(1.0, 1.0, 1.0));                                          \
    float _hx = PBRBaseHeight.SampleLevel(PBRBaseHeightSampler, float3((WP).yz / ((BASE_TILE) * (TRI_MUL)), (float)(BASE_IDX)), 0).g; \
    float _hy = PBRBaseHeight.SampleLevel(PBRBaseHeightSampler, float3((WP).xz / ((BASE_TILE) * (TRI_MUL)), (float)(BASE_IDX)), 0).g; \
    float _hz = PBRBaseHeight.SampleLevel(PBRBaseHeightSampler, float3((WP).xy / ((BASE_TILE) * (TRI_MUL)), (float)(BASE_IDX)), 0).g; \
    OUT_H = _hx * _absN.x + _hy * _absN.y + _hz * _absN.z;                               \
}
```

**采样次数**：每次调用 = 3 次 SampleLevel。raymarch 16 步 = 48 次 height 采样/像素（命中前）。secant refine 2 步 = 6 次/像素。极坏总计 ≈ 54 次。

> **共用 Triplanar 框架**：与 SAMPLE_PARAM_PBR 同样按 `pow(abs(dir), TriplanarSharpness)` 算 absN——TriplanarSharpness MID 参数仍是同一个值，无需新增。

### 2.2 HeightScale 与 BaseTexIdx 的 cell 加权

**D8.2.9 拍板**：raymarch 全程使用入射像素的三 cell 软边权重 wA/wB/wC（来自 R5 软边判定）做加权，而不是只看 dominant cell。这避免 cell 软边过渡处的 SHFRM 高度不连续：

```hlsl
// 在 raymarch 主流程之前预算（一次）
float4 lut0_A = CellAttrLUT.Load(int3(c0, 0, 0));
float4 lut0_B = CellAttrLUT.Load(int3(c1, 0, 0));
float4 lut0_C = CellAttrLUT.Load(int3(c2, 0, 0));
float4 lut3_A = CellNSpecLUT.Load(int3(c0, 0, 0));
float4 lut3_B = CellNSpecLUT.Load(int3(c1, 0, 0));
float4 lut3_C = CellNSpecLUT.Load(int3(c2, 0, 0));

int   baseA = (int)(lut0_A.r * 255.0 + 0.5);
int   baseB = (int)(lut0_B.r * 255.0 + 0.5);
int   baseC = (int)(lut0_C.r * 255.0 + 0.5);
float triMulA = lut3_A.a;
float triMulB = lut3_B.a;
float triMulC = lut3_C.a;
// HeightScale 用新增的 LUT3.G 字段（R8.0 留白，R8.2 激活；详见 §1.4 表）
float hScaleA = lut3_A.g * MaxRaymarchDepthCM;   // [0, 1] × MaxDepth → 实际 cm 量纲
float hScaleB = lut3_B.g * MaxRaymarchDepthCM;
float hScaleC = lut3_C.g * MaxRaymarchDepthCM;

float wsum = wA + wB + wC + 1e-6;
float hScale_blend = (hScaleA * wA + hScaleB * wB + hScaleC * wC) / wsum;

// raymarch 中每一步 height 采样取**软边权重最大的 cell** 的 BaseTexIdx 与 triMul，
// 因为单步只能采一组 base slice——三 cell 加权会导致同一像素 raymarch 路径上 BaseTexIdx 跳变
// 视觉差异：软边过渡区可能采到稍微不同的 height，但 hScale_blend 仍连续 → 高度场幅度连续
int   baseIdx_dom = (wA >= wB && wA >= wC) ? baseA : (wB >= wC ? baseB : baseC);
float triMul_dom  = (wA >= wB && wA >= wC) ? triMulA : (wB >= wC ? triMulB : triMulC);
```

> 软边过渡区（wA ≈ wB ≈ wC ≈ 0.33）的 BaseTexIdx 跳变是 raymarch 内部的次要瑕疵——视觉上比"三 cell 各 raymarch 一遍"便宜 3 倍，且 hScale_blend 是连续的（高度幅度无跳变），仅 BaseTexIdx 决定细节纹路。

### 2.3 SHFRM 主流程

放在 R8.1 主流程的 Step 6（软边权重 wA/wB/wC）之后、Step 7（三 cell PBR 采样）之前：

```hlsl
// =====================================================================
// R8.2 Step 6.5: Spherical Height Field Ray Marching
//
// 输入：
//   WorldPos      - 球面 baseline 上的世界坐标（VS 灌入）
//   CameraVector  - 视线方向（UE 提供：从像素指向相机）
//   c0/c1/c2 + wA/wB/wC - R5 软边权重（D8.2.3 共享起点）
//   PlanetCenter  - 球心（MID Vector 参数，R4 已注入）
//   GlobeRadiusCM - 球半径（MID Scalar 参数，R8.2 新增）
//   MaxRaymarchDepthCM - raymarch 沿视线最大深度（MID Scalar 参数，默认 75）
//
// 输出：
//   P_hit         - 真实地表交点世界坐标（替代 WorldPos 进入 Step 7）
//   hit_dir       - normalize(P_hit - PlanetCenter)（替代 dir 进入 Step 7）
//   OutPixelDepthOffset - (length(P_hit - CameraWorldPos) - length(WorldPos - CameraWorldPos))
// =====================================================================

// 默认值（grazing 路径用）
float3 P_hit    = WorldPos;
float3 hit_dir  = dir;
float  pixelDepthOffset = 0;

// grazing 检测（D8.2.5）：dot(rayDir, -dir) → cos(angle between view and outward normal)
float3 rayDir = -CameraVector;   // 注意：UE CameraVector 是从像素指向相机，rayDir 是相反
float grazingDot = dot(rayDir, -dir);   // -dir = 球心方向；rayDir·(-dir) = 视线穿入球的"深度"分量
float grazingMix = smoothstep(0.0, 0.2, grazingDot);  // 0=完全 grazing → 不做 raymarch；1=正面看 → 全 raymarch

// hScale_blend = 0 短路（海岸/海洋等 D8.2.6）
if (hScale_blend > 0.001 && grazingMix > 0.001)
{
    // ---- raymarch 主循环（D8.2.4：MinSteps=8, MaxSteps=24）----
    float prevDelta = 0;
    float t_hit = 1.0;   // 默认未命中：t = MaxDepth 处
    bool hit = false;

    [unroll]
    for (int step = 1; step <= 16; step++)   // 16 步线性
    {
        float t = (float)step / 16.0;
        float3 P_t = WorldPos - rayDir * (t * MaxRaymarchDepthCM);
        // 注：减号是因为我们沿视线"向相机方向"退（§1.3 拍板）

        float3 dir_t = normalize(P_t - PlanetCenter);
        float h_radial = length(P_t - PlanetCenter) - GlobeRadiusCM;

        // 该点的 height field 值（用 dominant cell 的 BaseTexIdx）
        float h_field;
        SAMPLE_HEIGHT_FIELD(dir_t, P_t, TileScale, baseIdx_dom, triMul_dom, h_field);
        h_field *= hScale_blend;   // 用三 cell 加权后的 HeightScaleCM

        float delta = h_radial - h_field;

        if (delta > 0 && step > 1)
        {
            // 已穿过地表 → secant refine（D8.2.4：2 步）
            t_hit = (float)(step - 1) / 16.0
                  + (1.0 / 16.0) * (-prevDelta) / (delta - prevDelta);
            hit = true;
            break;
        }
        prevDelta = delta;
    }

    if (hit)
    {
        // 二次 secant 提精（可选，R8.2 默认开启）
        float3 P_secant = WorldPos - rayDir * (t_hit * MaxRaymarchDepthCM);
        float3 dir_secant = normalize(P_secant - PlanetCenter);
        float h_field_s;
        SAMPLE_HEIGHT_FIELD(dir_secant, P_secant, TileScale, baseIdx_dom, triMul_dom, h_field_s);
        h_field_s *= hScale_blend;
        float h_radial_s = length(P_secant - PlanetCenter) - GlobeRadiusCM;
        // 一次 Newton step
        float refineDelta = h_radial_s - h_field_s;
        // 简化：如果 |refineDelta| > 0.1cm 再做一步；否则直接用 P_secant
        if (abs(refineDelta) < 0.1)
        {
            P_hit = P_secant;
        }
        else
        {
            // 退化：直接用 P_secant
            P_hit = P_secant;
        }
        hit_dir = normalize(P_hit - PlanetCenter);

        // grazing 软回退混合（D8.2.5）
        P_hit   = lerp(WorldPos, P_hit, grazingMix);
        hit_dir = normalize(lerp(dir, hit_dir, grazingMix));
        pixelDepthOffset = lerp(0, dot(P_hit - WorldPos, normalize(WorldPos - CameraWorldPos)), grazingMix);
    }
}

// ---- Step 7（R8.1）改为：用 P_hit 与 hit_dir 而非 WorldPos 与 dir ----
float3 albA, albB, albC;
float3 nrmA, nrmB, nrmC;
float  rghA, rghB, rghC;
SAMPLE_PARAM_PBR(c0, hit_dir, P_hit, TileScale,  albA, nrmA, rghA);
SAMPLE_PARAM_PBR(c1, hit_dir, P_hit, TileScale,  albB, nrmB, rghB);
SAMPLE_PARAM_PBR(c2, hit_dir, P_hit, TileScale,  albC, nrmC, rghC);

// ---- Step 8（R8.1）三层加权混合不变 ----
// （Albedo / NormalTS / Roughness 计算与 R8.1 一致）

// ---- Step 9（R8.2 新增）：写 PixelDepthOffset 到 Custom 节点 Additional Output ----
OutPixelDepthOffset = pixelDepthOffset;
```

**关键关注点**：

1. **rayDir = -CameraVector**：UE 的 `CameraVector` 节点输出从**像素指向相机**的单位向量；raymarch 的"视线方向"应该是**相机指向像素**，所以取负。
2. **rayDir · (-dir) 是 grazing 度量**：`-dir = ` 从球面点指向球心的方向；它与 rayDir 的点积反映"视线穿入球体的深度分量"，越接近 0 越 grazing。阈值 0.2（cos(78°)）够用。
3. **t_hit 的 secant 公式**：标准线性插值——`prevDelta` 是上一步（step-1）的 delta，`delta` 是当前步的 delta，命中点在两者之间。
4. **`length(P - C) - R`**：每步都重算径向高度，比"沿视线累积"精确——避免长 raymarch 路径的浮点累积误差。
5. **PixelDepthOffset 量纲**：相机空间 cm（不是世界空间）。`dot(P_hit - WorldPos, normalize(WorldPos - CameraWorldPos))` 把世界空间偏移投影到相机空间深度方向。
6. **grazing 路径下 t_hit = 1 + hit = false**：raymarch 走完 16 步未命中 → 全部使用 R8.1 的 WorldPos/dir 路径，且 PixelDepthOffset = 0。这是 D8.2.5 软回退的基础。

### 2.4 性能预算

| 阶段 | R8.1 | R8.2 |
| --- | --- | --- |
| LUT 查询（一次性）| 12 | **18**（+6：CellNSpecLUT 三 cell 中已包含，CellAttrLUT 三 cell 已包含；增量在 §2.2 的 baseIdx_dom + triMul_dom 选择，约 0 次新增；实际 18 = 与 R8.1 持平 + 几个标量计算）|
| Height raymarch（R8.2 新增）| 0 | **48~54**（16~18 步 × 3 平面 Triplanar）|
| PBR 三件套（命中后一次）| 27 | **27**（与 R8.1 完全相同）|
| Forest overlay 短路 | 0~27 | 0~27（与 R8.1 同款） |
| **总采样 / 像素** | **33** | **~81**（极坏 ~108）|
| **GPU 耗时（3060, 1080p）** | **3 ms** | **4~5 ms** |

> **比 POM 方案 B' 便宜的原因**：POM 要 3 cell × 3 件套 × 3 平面 = 27 次 PBR；SHFRM 命中后只算 1 次 PBR Triplanar（与 R8.1 完全一致 = 27 次），节省 = 0 次 PBR——但 POM 还要每个 cell 都加权再混合 ΔUV3D，3 cell 的全套 PBR 采样独立做导致总采样飙到 ~99~153。SHFRM 就一组 P_hit / hit_dir，下游 PBR 自然只算一次。

## 3. 已知技术陷阱与解决方案

### 3.1 视线进入球体时反向 raymarch 不收敛

**症状**：从球内部看球（编辑器经常拖镜头到球内）时，`grazingDot < 0`，软回退接管 → 整球退化为 R8.1 baseline。

**对策**：**接受**——球内部视角是**编辑器异常状态**，不是产品形态。如果用户主动拖镜头穿入，看到没有 SHFRM 也合理。

### 3.2 `MaxRaymarchDepthCM` 太大导致每像素 ~50 cm 的"远视距精度损失"

**症状**：山脉边缘的 silhouette 锯齿（raymarch 步长 = MaxDepth/16 = 4.7 cm，远小于像素覆盖球面尺寸 5 cm/pixel，所以理论上 OK；但极角 grazing 时步长沿视线投影到屏幕可能 < 1 pixel，引发 silhouette flickering）。

**对策**：MaxSteps 在 grazing 区自适应翻倍——但本期 R8.2 不做（`MaxRaymarchSteps` 是 MID Scalar 参数，编辑器手调即可）。

### 3.3 PBRBaseHeight 资产的灰度通道选择

**约定**：`PBRBaseHeight` 是 `Linear Color` Sampler Type，灰度信号在 **G 通道**（与 Roughness 一致）。资产端确保 `T_PBRBase_Height.uasset` 三个 slice 的 R/G/B 三通道**都是相同灰度值**（PNG 灰度图导入 UE 会自动复制到 RGB 三通道）。

### 3.4 与 SLW 水面层的视觉一致性

**症状**：海岸线 cell（`Coast.Beach`）如果 HeightScaleCM > 0，沙滩会被抬升 ~30 cm，但海面 mesh 仍在 `WaterRadiusCM = R + 100cm` 固定半径——会出现"沙滩下半部分泡在水里"的视觉错位。

**对策**：D8.2.6 拍板——`Coast.Beach` 与所有 `Ocean.*` 配方的 `HeightScaleCM = 0`。海面 mesh 不需要任何修改。

### 3.5 三 cell 软边过渡区的 BaseTexIdx 跳变

**症状**：cell A/B/C 的 BaseTexIdx 不同时（如 A=Soil/B=Rock/C=Soil），软边过渡区每像素的 dominant cell 可能在两个 cell 之间跳变 → height 采样源跳变 → 视觉上是"细窄边带的高度纹理切换"。

**对策**：因为 `hScale_blend` 是三 cell 加权连续的，**高度场幅度本身连续**——只是同一高度幅度下的纹理细节切换。视觉上是"texture seam"而不是"高度 seam"，肉眼难察觉。R8.3 / W4 可升级为"三 cell 各做 raymarch 后加权"消除这条瑕疵。

| HLSL Code | ~260 行 | **~330 行**（+70：SAMPLE_HEIGHT_FIELD 宏 + Step 6.5 主流程 + Step 9 PDO） |
| cpp 改动 | 0 行新增 | **~25 行**（FR8Recipe 加 1 字段 + 17 配方表加 1 列 + RebuildCellNSpecLUT_ 改 1 行 + ApplyTerrainMaterial_ 加 5 行 + 反射诊断 1 行 + UPROPERTY 2 个）|
| LUT 字段 | 不变 | **不变**（LUT3.G 字段从 R8.0 起预留，R8.2 激活）|
| 17 配方表 | 不变 | **+1 列 HeightScaleCM** |
| Material pin | BaseColor + Normal + Rough | **+ Pixel Depth Offset** |
| GPU 耗时 | 3 ms | **4~5 ms** |

### 8.2 与 T 阶段（自研球面网格）的关系

R8.2 完全工作在材质域 / PS 阶段，**与 T 阶段几何域 cpp 顶点位移无任何耦合**。具体分层（D8.2.7）：

| 尺度 | 来源 | 量纲 |
| --- | --- | --- |
| 大尺度山势（公里级）| T 阶段 cpp `MeshDisplacementBuilder::ComputeVertexElevationCM` | ~500 cm |
| 中尺度地形细节（十米级）| T6 LOD fbm（待落地）| ~10 cm（D8.2.8 待 T6 期细化） |
| **小尺度表面凹凸（厘米级）** | **R8.2 SHFRM** | **0~50 cm** |
| 微观纹理感（毫米）| Normal map（R8.1 已接通）| 视差错位 |

### 8.3 与 W4 的关系

W4 联调时，17 配方表中 `HeightScaleCM` 字段从 cpp 静态硬编码迁移到 `UTerrainDefinition::FTerrainMaterialParams.HeightScaleCM`。HLSL 端**不变**——`lut3.g * MaxRaymarchDepthCM` 还原 cm 值的逻辑 W4 仍沿用。

### 8.4 与 R9 多 LUT 的兼容

R9 加 Decor / Owner / Fog 三套独立 LUT 时，R8.2 的 SHFRM 路径**完全不影响**——SHFRM 只读 `CellAttrLUT.r`（BaseTexIdx）+ `CellNSpecLUT.g/a`（HeightScale + TriScale）。R9 新增的 LUT 在 Step 7（命中后 PBR 采样）阶段使用，与 SHFRM 正交。

## 9. 后续优化路径

### 9.1 R8.3 候选优化（不阻塞 R8.2 验收）

| 优化点 | 收益 | 代价 |
| --- | --- | --- |
| 三 cell 各做 raymarch 后加权 | 消除 §3.5 软边过渡区 BaseTexIdx 跳变 | GPU +200% raymarch 成本 |
| `MaxRaymarchSteps` 改 `[loop]` 动态步数 | 编辑器实时调步数 | HLSL 编译期优化损失，常态成本 +5% |
| Adaptive raymarch（grazing 区翻倍步数）| grazing silhouette 锯齿大幅减轻 | 极角附近 GPU +50% |
| Self-shadow（raymarch 沿光源方向）| 山脉接收阳光的真实自阴影 | GPU 翻 2 倍（每像素两次 raymarch）|

### 9.2 R8.4 / W4 / T6 联调候选

- W4：HeightScaleCM 从硬编码迁到 `UTerrainDefinition::FTerrainMaterialParams.HeightScaleCM`
- T6：fbm 上限 limit 到 ~10 cm，30~50 cm 留给 SHFRM（D8.2.8）
- R10 (LOD) 已迁至 [TessellatedMeshDesign.md §5.4](TessellatedMeshDesign.md#54-t6-lod-思路初稿)，与 R8.2 无耦合
