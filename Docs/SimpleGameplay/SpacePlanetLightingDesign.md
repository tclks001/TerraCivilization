# TerraCivilization SimpleGameplay 太空行星光照设计稿

> 本稿定义 SimpleGameplay 的默认视觉环境：一颗位于世界中心、由 HISM 球面瓦片组成的行星，悬浮于宇宙背景中。
>
> 目标不是复刻开放世界的昼夜天空，而是在保持地形、棋子、选中态与行动范围可读的前提下，让玩家第一眼明确感到“正在观察一颗太空中的行星”。
>
> 适用地图：`/Game/Map/TessellatedMeshTestMap`。本稿只涉及关卡 Actor、材质资产、后处理和验收，不改动 WorldGen、HISM 构建、玩法规则或相机交互接口。

---

## 1. 目标与设计原则

当前开放世界模板遗留的体积云、高度雾与蓝色天空，会在星球周围制造大气透视和地平线；这会使中心星球读成“漂浮在空气中的岩石球”。

本期采用 **玩法可读性优先的太空行星** 方向：

```text
深黑星空背景（Unlit / Emissive）
                ↓
低强度冷色环境补光（Sky Light）
                ↓
HISM 地表、棋子、交互高亮、可选水面
                ↑
单一太阳直射光（Directional Light）
```

核心原则：

- **太空必须是黑的**：背景不产生天空散射、雾化或地平线。
- **太阳必须塑形**：主光从侧前方照射，形成清晰但不过硬的昼夜分界，表现球体曲率。
- **夜面仍须可玩**：极弱冷色环境补光只服务于瓦片、棋子与交互状态辨识，不模拟地球夜空。
- **曝光必须稳定**：镜头转向星空或亮地表时，画面亮度不应自动跳变。
- **视觉层级服从玩法**：棋子、黄色选中态、蓝色行动范围和 Cell 高亮必须比地表和星空更易识别。

## 2. 场景组成与取舍

| 模块 | 本期方案 | 原因 |
| --- | --- | --- |
| 天空背景 | 反向球或天空盒，`Unlit` 星图材质 | 不受光照和曝光波动影响；没有天空地平线 |
| 太阳 | 一盏可移动 `Directional Light` | 以稳定的单方向光塑造球体与地形起伏 |
| 环境光 | 一盏低强度 `Sky Light`，深蓝黑环境 | 保留夜面玩法信息，避免背光面完全丢失 |
| 雾 | 无 `ExponentialHeightFog` | 太空中不应出现距离雾与蓝灰洗色 |
| 云 | 无 `VolumetricCloud` | 云层会把场景重新解释为地面天空 |
| 大气边缘 | 可选薄球壳 Fresnel | 只提供行星轮廓，不引入全场天空散射 |
| 后处理 | 无边界 `Post Process Volume`，固定曝光 | 保持视角切换和交互时的亮度一致 |

本期不使用 UE 开放世界模板的 `BP_SkySphere`、日夜循环天空蓝图、体积云或大气散射作为主视觉基础。

## 3. 关卡 Actor 清单

在 `TessellatedMeshTestMap` 中建立或保留以下 Actor；名称可按项目现有命名规范调整，但职责必须保持一一对应。

| Actor | 建议名称 | 关键配置 | 职责 |
| --- | --- | --- | --- |
| Directional Light | `DL_Sun` | Movable，单一主光 | 形成受光半球、阴影和昼夜分界 |
| Sky Light | `SL_SpaceAmbient` | Movable，低强度，指定暗色 Cubemap | 提供极弱夜面补光与材质环境反射 |
| Post Process Volume | `PPV_SpacePlanet` | `Infinite Extent` | 锁定曝光、统一 Bloom 与颜色层级 |
| Static Mesh Actor | `SM_SpaceSky` | 反向球或天空盒，Unlit 材质 | 提供星空背景 |
| Static Mesh Actor，可选 | `SM_PlanetAtmosphere` | 比星球略大的球壳 | 提供边缘大气辉光 |

以下开放世界模板 Actor 必须删除、禁用或在本地图隐藏：

- `VolumetricCloud`
- `ExponentialHeightFog`
- `BP_SkySphere` 或其同类天空球
- 产生蓝天散射的 `SkyAtmosphere`
- 仅为模板地平线服务的地形、水面或远景网格

若项目其他测试地图仍需要原有天空环境，应只在 `TessellatedMeshTestMap` 移除，不要修改全局共用蓝图资产。

## 4. 主太阳光设计

### 4.1 初始参数

| 属性 | `DL_Sun` 初始值 | 调参范围 | 说明 |
| --- | ---: | ---: | --- |
| Mobility | `Movable` | 固定 | 便于后续旋转太阳方向或加入时间流逝 |
| Intensity | `5 lux` | `3 - 10 lux` | 从低值起步，最终由固定曝光共同决定 |
| Light Color / Temperature | `5600 K` | `5200 - 5800 K` | 略暖白，不应呈橙色夕阳 |
| Source Angle | `0.5 deg` | `0.3 - 1.0 deg` | 保持太阳感，同时减轻地形阴影锯齿 |
| Cast Shadows | 开启 | 固定 | 地形和棋子需要接触阴影与形体层次 |
| Atmosphere Sun Light | 关闭 | 固定 | 本期不依赖 `SkyAtmosphere` |

### 4.2 构图约定

太阳方向应从当前主相机的侧前方进入画面，优先让镜头同时看到：

- 大约 `60% - 75%` 的受光可见面；
- 一条清晰、弧形的昼夜分界；
- 面向镜头的地表起伏和瓦片边界；
- 非纯黑的少量背光区域。

不要把太阳直接放在相机正后方：这会消除昼夜线，球体会变成正面均匀受光的“材质样球”。也不要让太阳正对相机：会压暗可见面并使高亮区域与 UI / Cell 高亮竞争。

### 4.3 HISM 与法线前置检查

球面 HISM 瓦片和任何后续主地表网格的法线必须朝外，即与 `Cell.UnitCenter` 同方向。若法线反向，`Directional Light` 下会出现整面发黑、昼夜线错误或局部三角面闪断。

本项沿用 [HISMSphericalTileRenderDesign.md](HISMSphericalTileRenderDesign.md) 的球面朝向契约；光照验收不能用关闭主光绕过法线问题。

## 5. 环境补光与反射

### 5.1 Sky Light

`SL_SpaceAmbient` 不模拟白天天空，而是一个受控的玩法补光源。

| 属性 | 初始值 | 调参范围 | 验收意图 |
| --- | ---: | ---: | --- |
| Source Type | Specified Cubemap | 固定 | 使用独立太空环境，不捕捉地表 |
| Cubemap 主色 | 深蓝黑 | 固定 | 仅在阴影中保留一点冷色层次 |
| Intensity Scale | `0.06` | `0.03 - 0.10` | 让背光面可读，不抹平昼夜差异 |
| Real Time Capture | 关闭 | 固定 | 星空背景无需每帧捕捉；避免引入意外亮度 |
| Lower Hemisphere | 深黑 | 固定 | 避免从“地面”方向反射出灰色填充 |

### 5.2 可读性阈值

在背光侧，玩家应能分辨：

- 平原、森林、山脉的基础类别；
- 棋子的阵营主色和轮廓；
- 黄色选中、蓝色可行动范围、hover / target 高亮；
- 大致的 Cell 边界与局部地形起伏。

背光侧不要求读出高频地表纹理，也不应和受光侧亮度接近。若夜面像阴天白昼，优先降低 `Sky Light Intensity Scale`，不要先降低太阳强度。

## 6. 星空背景材质与资产

### 6.1 几何与层级

`SM_SpaceSky` 使用包住相机和行星的反向球或天空盒：

```text
SpaceSky Radius > 最大相机距离 + GlobeRadiusCM
Material = M_SpaceSky (Unlit)
Cast Shadow = false
Collision = NoCollision
```

背景网格必须不投射、不接收阴影，也不参与碰撞或 Cell 拾取。它的半径只服务于可见性，不能被当作任何玩法空间的边界。

### 6.2 `M_SpaceSky` 材质约定

| 项目 | 设置 |
| --- | --- |
| Material Domain | Surface |
| Blend Mode | Opaque |
| Shading Model | Unlit |
| Two Sided | 依反向球网格法线决定；天空盒通常不需要 |
| Base Color | 不使用 |
| Emissive Color | 星图或 Cubemap 采样结果 |
| Roughness / Specular | 不使用 |

星空内容采用暗黑底色加稀疏星点，不使用明显云气、银河大面积亮带或高饱和蓝紫渐变。初版可使用静态 HDRI / Cubemap；后续若需要星空旋转，再只旋转材质采样坐标，不移动行星或光源。

### 6.3 亮度原则

- 星点的峰值亮度可以高于背景，但 Bloom 后不应抢过棋子或选中高亮。
- 背景平均亮度必须低于行星背光面。
- 不在背景中放置明亮太阳贴图；太阳方向由 `DL_Sun` 表达。若后续需要可见太阳盘，应由独立 Sprite / Billboard 与光向联动，并延后到美术表现阶段。

## 7. 后处理与颜色层级

### 7.1 `PPV_SpacePlanet` 初始设置

| 类别 | 属性 | 初始值 | 说明 |
| --- | --- | ---: | --- |
| Exposure | Metering Mode | Manual | 禁止镜头朝星空 / 地表时自动补偿 |
| Exposure | Exposure Compensation | `0.0` | 与 `DL_Sun` 强度成对微调 |
| Bloom | Intensity | `0.2` | 仅给星点、轮廓和水面高光少量辉光 |
| Bloom | Threshold | `1.5` | 避免普通地表整体泛光 |
| Color Grading | Global Saturation | `0.95` | 压住地表过饱和，保留阵营色识别 |
| Color Grading | Shadows Tint | 极弱蓝青 | 与空间补光一致，不做紫色化 |
| Local Exposure | 默认关闭 | 固定 | 初版避免局部曝光改变 Cell 高亮对比 |

项目当前已启用扩展亮度范围。固定曝光的具体 EV 数值依赖最终太阳强度、地表材质和显示器校准，因此本稿以“先锁定，再联合调整太阳强度与补偿”为准，不把单一 EV 值写死。

### 7.2 调参顺序

必须按以下顺序调参，避免用后处理掩盖光照问题：

1. 先关闭雾、云和天空散射，确认背景是纯黑星空。
2. 固定曝光。
3. 调 `DL_Sun` 方向，获得正确昼夜分界和可见面构图。
4. 调 `DL_Sun` 强度，使受光面材质不发灰、不溢白。
5. 调 `SL_SpaceAmbient`，只补到夜面可操作的最低值。
6. 最后调 Bloom、饱和度和阴影色调。

## 8. 可选行星大气薄壳

大气薄壳是用于建立尺度感的局部视觉层，不是天空系统；它默认放在 SL4，前置光照完成后再决定是否保留。

### 8.1 几何约定

```text
AtmosphereRadius = GlobeRadiusCM * 1.003 - 1.010
Mesh = sphere shell
Collision = NoCollision
Cast Shadow = false
```

壳体不应厚到能在行星正面形成蓝色滤镜，只应在轮廓边缘出现很淡的青蓝色 / 冷白色辉光。

### 8.2 `M_PlanetAtmosphere` 材质约定

| 项目 | 设置 |
| --- | --- |
| Shading Model | Unlit |
| Blend Mode | Additive 或 Translucent，按实际排序结果选择 |
| 核心遮罩 | `pow(1 - saturate(dot(NormalWS, ViewDirectionWS)), RimPower)` |
| Emissive | 冷蓝白，低强度 |
| 光向调制 | 可选，仅让朝太阳一侧略亮 |

若透明排序、TAA 抖动或水面反射出现明显问题，初版直接关闭该 Actor。太空感的主验收来自黑色背景、单向太阳与稳定曝光，不依赖大气壳。

## 9. 交互与玩法表现约束

光照系统必须让以下已有或计划中的表现保持优先级：

| 表现 | 约束 |
| --- | --- |
| 阵营棋子 | 在受光和背光两侧均可依据主色、轮廓区分 |
| 当前选中 | 黄色高亮不被太阳高光或 Bloom 淹没 |
| 行动范围 | 蓝色范围与冷色夜面仍有足够明度 / 色相对比 |
| Hover / Target | 近距离可读，不因局部阴影变成黑块 |
| 地形类型 | 平原、森林、山脉在受光侧清楚区分，背光侧保留最低可读性 |
| 相机 | 绕球、缩放或切焦点时，曝光不泵动，背景没有地平线穿帮 |

如需为了可读性在棋子材质中加入轻微 Fresnel 或受控 Emissive，应单独作为棋子表现任务处理；本光照稿不直接修改棋子材质，以免用全局环境解决局部 UI 问题。

## 10. 实现里程碑与验收成果

### SL1：清除开放世界天空遗留

**阶段目标**

把 `TessellatedMeshTestMap` 从开放世界模板环境还原为“只有行星和玩法对象的黑色舞台”。本阶段故意不加入星空、太阳、环境补光或大气壳；清理后星球发黑、背景全黑是预期中间状态，不能用模板天空或自动曝光把它重新“补亮”。

**范围与保护对象**

| 类别 | SL1 处理方式 | 典型名称 / 搜索词 | 说明 |
| --- | --- | --- | --- |
| 体积云 | 删除或隐藏 | `VolumetricCloud` | 完全不属于太空场景 |
| 高度雾 | 删除或隐藏 | `ExponentialHeightFog` | 去除蓝灰距离雾与地平线雾带 |
| 大气散射 | 删除或隐藏 | `SkyAtmosphere` | 去除蓝天、太阳散射与天空地平线 |
| 模板天空球 | 删除或隐藏 | `BP_SkySphere`、`SkySphere` | 去除蓝色天空贴图和云层材质 |
| 日夜天空控制器 | 禁用或移出本地图 | `Sky`、`TimeOfDay`、`SunSky` | 防止运行时重新驱动天空 / 太阳 |
| 远景地平线 | 删除或隐藏 | `Landscape`、`Ocean`、`WaterBody`、`Backdrop` | 只处理为模板天空服务的资产 |
| 行星与玩法对象 | 必须保留 | `Planet`、`TessellatedMesh`、`HISM`、`Piece`、`Interaction`、`Camera` | 这些不属于环境清理范围 |

> 名称只是 Outliner 搜索起点。最终依据是 Actor 的类型与可见效果，不依据名称猜测；例如项目自定义 `BP_SpaceSky` 不应因名称含 `Sky` 被误删。

**编辑器操作步骤**

1. 打开 `/Game/Map/TessellatedMeshTestMap`，先 `Save Current`，确保本次修改只发生在该地图。
2. 在 World Outliner 依次搜索 `VolumetricCloud`、`ExponentialHeightFog`、`SkyAtmosphere`、`SkySphere`、`SunSky`、`Landscape`、`Ocean`、`WaterBody` 和 `Backdrop`。每次只处理一个搜索结果，便于确认对应的可见效果。
3. 对来源明确、只在本地图服务于天空的 Actor，优先用 `Delete` 删除；若无法判断是否被其他地图、Level Instance 或运行时蓝图依赖，先在 Details 中关闭 `Actor Hidden In Game`，并在 Outliner 关闭可见性，记录名称后再做 PIE 验证。
4. 对 `SkyAtmosphere`，确认场景里不存在第二个同类 Actor 后再删除 / 隐藏。保留多个大气 Actor 会使排错失去意义。
5. 对 `Directional Light` 不在本阶段做最终调参：若它是模板太阳，可暂时保留但不要删除；SL2 会统一命名、设置方向与强度。若其勾选了 `Atmosphere Sun Light`，可先取消该勾选，避免剩余大气 Actor 继续响应它。
6. 不删除 `APlanetTessellatedMesh` / `BP_PlanetTessellatedMesh`、HISM 组件、棋子 Actor、相机 Actor、交互控制器、`Post Process Volume` 或为棋子 / 高亮服务的材质资产。它们即使在黑色环境下看起来不美观，也不属于 SL1。
7. 清理完成后保存地图，关闭并重新打开该地图一次，确认不是通过临时 Editor 视口状态才看起来正确。

**建议的安全操作顺序**

```text
先隐藏一个候选环境 Actor
        ↓
观察编辑器视口：蓝天 / 云 / 雾是否消失
        ↓
PIE 验证：是否有蓝图在 BeginPlay 重新生成或重新显示它
        ↓
确认只影响模板环境后，删除该 Actor 并保存地图
```

若地图使用 World Partition 或 External Actors，删除后需要在 Outliner 中确认对应 Actor 不再出现，并保存所有提示保存的 External Actor 包；不要只保存 `.umap` 后忽略未保存项。

**清理后的预期画面**

| 画面元素 | SL1 完成后的预期 | 是否异常 |
| --- | --- | --- |
| 行星外背景 | 纯黑或接近纯黑 | 正常；SL2 才加入星空 |
| 体积云、云影 | 完全不存在 | 正常 |
| 蓝色天空 / 地平线 | 完全不存在 | 正常 |
| 高度雾造成的远处洗灰 | 完全不存在 | 正常 |
| 地表背光侧 | 可能很暗甚至接近黑 | 正常；SL3 才解决可读性补光 |
| 地表受光侧 | 可能仍受旧 Directional Light 影响 | 允许；SL2 再统一太阳参数 |
| 自动曝光造成的暂时变亮 | 可能仍存在 | 允许；SL3 再锁定曝光 |

**验收步骤**

1. 在编辑器默认视口将相机绕行星旋转一周，并拉远到能同时看到完整球体和背景的距离。
2. 确认任意方向均没有蓝色天空、云层、雾带、海平线或远景地面；背景允许是纯黑。
3. 在 Outliner 分别搜索 `VolumetricCloud`、`ExponentialHeightFog`、`SkyAtmosphere` 和 `SkySphere`，当前地图不应存在处于可见状态的模板环境 Actor。
4. PIE 启动后重复第 1、2 步。若天空在 PIE 才恢复，检查 Level Blueprint、`BeginPlay`、`SunSky` 或其他天空控制蓝图是否在运行时 Spawn / Unhide 了环境 Actor。
5. 在 PIE 中完成一次现有的 hover、选中棋子、显示可行动 Cell、移动或结束回合操作；确认鼠标射线仍命中 HISM 瓦片，棋子与交互高亮逻辑没有失效。
6. 退出 PIE 后再次检查编辑器视口，确认没有因 PIE 退出导致行星材质、HISM 实例或棋子变为默认棋盘格；若发生，按现有材质 / OnConstruction 恢复链路排查，不把它归因为天空清理。

**验收成果**

- `TessellatedMeshTestMap` 在编辑器与 PIE 中都不再呈现蓝天、体积云、高度雾、地平线或任何开放世界模板环境特征。
- 摄像机可在行星四周移动，行星以外空间始终是黑色舞台；尚无星空、太阳重调或补光是符合阶段边界的。
- HISM 球面瓦片、碰撞、Cell hover、棋子选择、行动范围高亮和基本移动流程可照常运行。
- 没有其他地图或共用资产被修改；本阶段变更仅保存在 `TessellatedMeshTestMap` 及其 External Actor 数据中。

**本阶段退出条件**

仅当“模板环境已彻底退出当前地图”与“玩法回归无误”同时成立，才能进入 SL2。若仍能看到任何一条蓝色地平线或云层，应先完成本阶段排错，不能用星空盒覆盖它。

### SL2：星空背景与单太阳定向光

**工作内容**

- 新建并挂载 `SM_SpaceSky` 与 `M_SpaceSky`。
- 添加 `DL_Sun`，按第 4 节参数建立单一主光。
- 调整太阳方向，使主相机默认构图能同时看到受光面和昼夜线。

**验收成果**

- 玩家第一眼能把场景读成“黑色宇宙中的球形行星”。
- 星球受光面具有连续的球面明暗变化，昼夜分界为弧形。
- 星空不投影、不遮挡、不响应光照，也不干扰拾取。

### SL3：环境补光与固定曝光

**工作内容**

- 添加 `SL_SpaceAmbient`，使用指定深蓝黑 Cubemap。
- 添加无限范围 `PPV_SpacePlanet`，设为手动曝光。
- 按第 7.2 节顺序联合调整主光、补光与曝光。

**验收成果**

- 镜头由地表转向星空、绕到夜面或缩放时，亮度不出现明显自动泵动。
- 背光面保留地形、棋子与交互状态的最低可读性，但明显暗于受光面。
- 受光地表不泛白，夜面不被补成阴天白昼。

### SL4：视觉层级精修与可选大气边缘

**工作内容**

- 调整 Bloom、色彩分级、太阳角度与阴影细节。
- 可选制作 `SM_PlanetAtmosphere` 和 `M_PlanetAtmosphere`，只在不干扰透明渲染时启用。
- 在完整玩法操作流程中检查高亮、棋子和地形对比。

**验收成果**

- 黄色选中、蓝色行动范围、阵营棋子在昼面与夜面都比普通地表更易识别。
- 星球边缘存在自然的轮廓分离；启用大气壳时，不出现整球发蓝、透明排序或 TAA 闪烁。
- 画面没有雾感、地表天空感或过强的模板化 Bloom。

### SL5：回归验收与参数固化

**工作内容**

- 在编辑器视口、PIE、不同相机距离和完整回合流程中回归。
- 将最终 Actor 参数记录到本稿附录或关卡备注；若未来需要太阳旋转，只暴露光向，不恢复天空系统。

**验收成果**

- 编辑器与 PIE 的背景、主光、曝光和交互可读性一致。
- 不影响 HISM 球面瓦片、碰撞、棋子选择、移动、相机聚焦与后续水面表现。
- 场景稳定地呈现为“宇宙中的可操作行星”，而非漂浮在蓝天中的岩石球。

## 11. 验收步骤

### 11.1 静态视觉验收

1. 打开 `TessellatedMeshTestMap`，确认 SL1 遗留 Actor 已移除或禁用。
2. 在默认镜头检查星空完整包围画面，背景没有云、雾或天空地平线。
3. 调整相机至昼夜线附近，确认球体曲率、山地和瓦片起伏由太阳光清楚表达。
4. 转到背光面，确认球面仍然可见但明显较暗。

### 11.2 玩法可读性验收

1. PIE 启动。
2. 依次选择不同阵营棋子，检查阵营色和黄色选中态在昼面、夜面均可辨认。
3. 触发可移动 / 可跳跃 Cell，检查蓝色高亮没有与夜面补光或星空混淆。
4. 执行一次相机聚焦、手动绕球、缩放、移动和回合切换，确认曝光稳定。

### 11.3 极端视角验收

1. 镜头朝向纯星空，随后快速回到受光地表；亮度不应有明显缓慢适应过程。
2. 镜头贴近地表，再拉远到可见完整行星；背景与行星边缘不应出现雾层、蓝色填充或裁切穿帮。
3. 让太阳位于侧后方和侧前方各检查一次；确认只有构图变化，没有地表整面反黑或法线错误。

## 12. 风险与排错

| 症状 | 常见原因 | 修复 |
| --- | --- | --- |
| 背景仍是蓝天 / 有云 | 模板 `SkyAtmosphere`、`VolumetricCloud` 或天空球仍在生效 | 在当前地图逐项禁用并确认无全局天空蓝图重新生成 |
| 球体像灰色无层次石头 | 太阳与相机同向，或环境补光过强 | 先调整太阳至侧前方，再降低 `Sky Light` |
| 夜面完全看不见棋子 | `Sky Light` 为零、曝光过低或棋子材质过暗 | 小幅提高 `Sky Light`；不先提高 Bloom |
| 夜面像白天 | `Sky Light` 过强或 Cubemap 太亮 | 降到 `0.03 - 0.10` 区间，并使用深蓝黑 Cubemap |
| 旋转镜头时亮度跳变 | 自动曝光或 Local Exposure 仍在运行 | `PPV` 设为 Manual，并确认优先级和无限范围 |
| 昼夜线呈三角块 / 阶梯 | HISM 或地表网格顶点法线不连续、朝向错误 | 检查法线朝外以及球面瓦片的平滑法线链路 |
| 选中黄 / 行动蓝被吞没 | Bloom 过强或地表 / 夜面饱和度竞争 | 先降低 Bloom，再调交互材质的明度对比 |
| 大气壳闪烁 / 排序错误 | 半透明材质与水面或后处理冲突 | 关闭大气壳；它不是本期核心依赖 |

## 13. 初版不处理的问题

- 真实物理大气散射、Rayleigh / Mie 参数化和地平线日落。
- 可见太阳盘、太阳耀斑、日食或星空旋转动画。
- 基于真实经纬度的日夜循环。
- 城市夜灯、云层阴影、极光、行星环或邻近天体。
- 为光照单独修改棋子、地表或水面材质配方。
- 为单个透明效果切换全项目 Forward Shading。

上述内容均应建立在 SL1 - SL5 已稳定通过后，再作为独立表现任务评估。

## 14. 完成定义

当 SL5 通过时，`TessellatedMeshTestMap` 应满足以下一句话目标：

> 玩家在任何常规操作镜头下，都能把场景读成一颗悬浮在黑色宇宙中的可操作行星；太阳塑造球体，夜面保留玩法信息，背景与后处理不再把它误导成蓝天中的岩石球。
