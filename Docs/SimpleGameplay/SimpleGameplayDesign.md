# TerraCivilization 简易玩法设计稿

> 本稿用于替代 [TechnicalDesign.md](TechnicalDesign.md) 中过重的首版玩法设想，作为当前阶段实现 **最小可玩回合制棋盘玩法** 的依据。
>
> 核心关键词：**12 个五边形阵营基地 + 球面 Hex/Pent 棋盘 + 二吃一 + 跳棋式连跳 + 三兵种 + 三地形**。

---

## 1. 当前项目基础与本稿定位

### 1.1 当前已具备的基础

当前项目已经具备实现本玩法所需的底层条件：

- **球面拓扑**：`Grid` 模块已经提供 `FSphereTopology`、`FCell`、`FCellEdge`、`FCorner` 等结构。
- **Cell 邻接图**：每个 `FCell` 通过 `NeighborCellIds` 保存 5 或 6 个邻居，玩法移动、攻击、开局布阵都应基于该邻接图实现。
- **12 个五边形不变量**：球面上恰好有 12 个 `bIsPentagon=true` 的 Cell，且永远是 5 邻接，天然适合作为 12 个阵营的大本营。
- **半径查询**：`FSphereTopologyQuery::CollectCellRing` / `CollectCellDisk` 已支持基于邻接 BFS 的环 / 圆盘查询，可直接用于开局半径 2 布阵。
- **地形生成与地形 Tag 基础**：已有 `TerrainTags` 与 `WorldGen` 模块，可将复杂地理临时收敛为三类玩法地形：平原、森林、山脉。
- **球面渲染与交互**：`TerraCivilization` 主模块已有 `APlanetTessellatedMesh`、`APlanetBinder`、`APlanetInteractionController`、`UCellHighlightComponent`，可以支持鼠标 hover / click 选择 Cell 与高亮。

### 1.2 当前尚未落地的部分

以下系统目前主要仍停留在复杂设计稿中，尚未形成独立源码模块：

- 棋子 / 棋盘运行时状态。
- 回合制管理。
- 移动、连跳、吃子判定。
- 胜负判定。
- UI 行动面板与回合面板。

因此，本稿的目标不是继续扩展复杂的 GAS / DataAsset 玩法框架，而是先定义一套 **可以直接基于 Cell 邻接图实现的简化棋类规则**。

## 2. 玩法总览

### 2.1 基本设定

- 球面棋盘由 `FSphereTopology.Cells` 构成。
- 棋盘上有 **12 个阵营**。
- 每个阵营驻扎在一个五边形 Cell 上。
- 每个五边形 Cell 是该阵营的 **大本营 / 中军帐 / 军旗 Cell**。
- 每个阵营开局拥有 **16 个棋子**：
  - 1 个军旗。
  - 5 个步兵。
  - 5 个骑兵。
  - 5 个弓兵。
- 玩家按回合行动。
- 每个玩家每回合选择 **1 个可移动棋子** 执行一次行动。
- 一次行动可以是：
  - 普通移动 1 格。
  - 跳跃。
  - 连续多次跳跃。
- 行动结束后，根据“二吃一”规则结算吃子。
- 若某阵营的军旗被吃掉，该阵营失败。

### 2.2 设计目标

这套玩法要做到：

- **规则少**：只有三兵种、三地形、一个核心吃子规则。
- **实现直接**：只依赖 `FCell.NeighborCellIds`，不需要复杂寻路、数值战斗或技能系统。
- **球面特色明确**：12 个五边形天然对应 12 个阵营，pent 周围半径 2 正好容纳 16 个开局棋子。
- **策略点清晰**：通过连跳制造阵型，通过二吃一吃子，通过地形限制远程和骑兵。

## 3. 棋盘、阵营与开局布阵

### 3.1 棋盘 Cell

玩法层只关心逻辑 Cell：

- Cell 是棋子站位的最小单位。
- Cell 之间通过 `NeighborCellIds` 相邻。
- 普通 Cell 通常是六边形，拥有 6 个邻居。
- 五边形 Cell 拥有 5 个邻居。
- 所有移动、跳跃、攻击线判定都发生在 Cell 邻接图上。

### 3.2 阵营基地

- 取全部 `bIsPentagon=true` 的 Cell 作为 12 个阵营基地。
- 建议初版直接使用 `CellId` 从小到大排序后的 12 个五边形作为阵营 `FactionId=0..11` 的基地。
- 每个基地 Cell 上放置本阵营的军旗。
- 军旗所在 Cell 即该阵营的大本营中心。

### 3.3 开局半径 2 布阵

每个阵营使用以大本营为中心、图距离不超过 2 的五边形区域布阵：

- 半径 0：中心 Cell，共 1 格。
- 半径 1：五边形周围 5 格。
- 半径 2：外圈 10 格。
- 合计：`1 + 5 + 10 = 16` 格。

布阵规则：

| 圈层 | 数量 | 放置内容 |
| --- | --- | --- |
| 半径 0 | 1 | 军旗 |
| 半径 1 | 5 | 弓兵 |
| 半径 2 | 10 | 5 个骑兵 + 5 个步兵 |

外圈布阵规则：

- 骑兵位于每个弓兵背向大本营方向的第二圈 Cell。
- 步兵位于相邻两个骑兵之间的第二圈 Cell。

初始化写入 `Pieces` 数组时，先计算本阵营全部开局 Cell，再按固定兵种顺序追加棋子，使遍历一个玩家所有棋子时保持恒定顺序：

```text
Flag = 0
Archer = 1,2,3,4,5
Cavalry = 6,7,8,9,10
Infantry = 11,12,13,14,15
```

如果后续需要阵营差异，可以再把外圈顺序改为配置项。

## 4. 棋子类型

### 4.1 通用棋子字段

初版每个棋子至少需要记录：

| 字段 | 含义 |
| --- | --- |
| `PieceId` | 棋子唯一 ID |
| `OwnerFactionId` | 所属阵营 |
| `CellId` | 当前所在 Cell |
| `PieceType` | `Flag` / `Infantry` / `Cavalry` / `Archer` |
| `bAlive` | 是否仍在棋盘上 |
| `bCanMove` | 是否可主动移动 |

### 4.2 军旗

| 属性 | 规则 |
| --- | --- |
| 数量 | 每阵营 1 个 |
| 初始位置 | 大本营中心五边形 Cell |
| 能否移动 | 不能移动 |
| 能否跳跃 | 不能跳跃 |
| 能否参与吃子 | 可以 |
| 被吃后果 | 所属阵营失败 |

军旗虽然不能主动移动，但它仍是本方棋子，可以在二吃一判定中作为友方棋子参与阵型。

示例：

```text
军旗A  友方A  敌方B
```

如果该直线阵型由本回合行动形成，则可以吃掉 `B`。

### 4.3 步兵

| 属性 | 规则 |
| --- | --- |
| 数量 | 每阵营 5 个 |
| 普通移动 | 可移动到相邻空 Cell |
| 标准跳跃 | 可跳过 1 个相邻棋子，落到其后方第 1 个空 Cell |
| 连跳 | 可以 |
| 特殊吃子能力 | 无 |

步兵是基础兵种，只使用通用移动、跳跃、二吃一规则。

### 4.4 骑兵

| 属性 | 规则 |
| --- | --- |
| 数量 | 每阵营 5 个 |
| 普通移动 | 可移动到相邻空 Cell |
| 标准跳跃 | 可以 |
| 连跳 | 可以 |
| 特殊能力 | 骑兵跳跃落点可以比标准跳跃多 1 格 |
| 地形限制 | 不可进入山脉，也不可跳跃跨过山脉 |

骑兵的特殊跳跃解释：

- 标准跳跃：从起点越过相邻 1 个棋子，落到该棋子后方第 1 个空 Cell。
- 骑兵跳跃：从起点越过相邻 1 个棋子后，可以继续多前进 1 格，落到后方第 2 个空 Cell。

符号示意：

```text
标准跳跃：A' A -   =>   - A A'
骑兵跳跃：A' B - - =>   - B - A'
```

其中：

- `A'` 表示正在行动的骑兵。
- `A` / `B` 表示被跳过的棋子，可以是友方或敌方。
- `-` 表示空 Cell。

> 初版建议：骑兵执行特殊跳跃时，中间路径上的落点 Cell 与最终落点 Cell 都不能是山脉。

### 4.5 弓兵

| 属性 | 规则 |
| --- | --- |
| 数量 | 每阵营 5 个 |
| 普通移动 | 可移动到相邻空 Cell |
| 标准跳跃 | 可以 |
| 连跳 | 可以 |
| 特殊能力 | 延长二吃一攻击距离 |
| 地形加成 | 弓兵位于山脉时，攻击距离再延长 1 格 |
| 地形克制 | 森林中的目标不受弓兵远程吃子影响 |

弓兵的特殊吃子不是直接射击，而是二吃一规则的远程变体。

普通二吃一：

```text
A A B
```

弓兵远程二吃一：

```text
A' A - B
```

山脉弓兵远程二吃一：

```text
A' A - - B
```

其中：

- `A'` 是弓兵，也是远程攻击者。
- `A` 是本方先锋 / 牵制棋子。
- `B` 是敌方目标。
- `-` 是空 Cell。

限制：

- 若 `B` 所在地形是森林，则该弓兵远程吃子无效。
- 若弓兵不在山脉，则只能使用 `A' A - B`。
- 若弓兵在山脉，则可以使用 `A' A - - B`。
- 山脉加成只影响弓兵远程吃子距离，不改变弓兵移动规则。

## 5. 地形规则

初版只保留三种地形。

| 地形 | 规则 |
| --- | --- |
| 平原 | 基础地形，无额外效果 |
| 森林 | 位于森林中的棋子不受弓兵远程吃子影响 |
| 山脉 | 骑兵不可进入、不可跳跃跨过；弓兵位于山脉时远程吃子距离 +1 |

### 5.1 平原

- 所有棋子都可以进入。
- 不影响普通移动、跳跃和吃子。

### 5.2 森林

森林只影响 **目标被弓兵远程吃子**：

```text
A' A - B
```

如果 `B` 位于森林，则弓兵 `A'` 不能通过该远程阵型吃掉 `B`。

注意：

- 森林不阻止普通二吃一。
- 森林不阻止棋子移动或跳跃。
- 森林不保护目标免受非弓兵的普通二吃一。

### 5.3 山脉

山脉有两个效果：

- **限制骑兵**：
  - 骑兵不能移动进入山脉 Cell。
  - 骑兵不能跳跃跨过山脉 Cell。
  - 骑兵特殊跳跃路径上的中间 Cell 和最终 Cell 都不能是山脉。
- **强化弓兵**：
  - 弓兵位于山脉 Cell 时，远程吃子从 `A' A - B` 延长为 `A' A - - B`。

## 6. 回合与行动规则

### 6.1 回合顺序

- 12 个阵营按固定顺序轮流行动。
- 初版建议使用 `FactionId=0..11` 的循环顺序。
- 已失败阵营跳过回合。
- 每个阵营回合内只能选择 1 个可移动棋子行动。

### 6.2 单次行动

一次行动包含：

1. 选择一个本方可移动棋子。
2. 执行普通移动或跳跃 / 连跳。
3. 行动结束后结算吃子。
4. 若有军旗被吃，立即结算失败。
5. 切换到下一个仍存活阵营。

### 6.3 普通移动

普通移动规则：

- 起点必须是当前玩家的可移动棋子。
- 目标 Cell 必须与起点相邻。
- 目标 Cell 必须为空。
- 目标地形必须允许该棋子进入。
- 普通移动只能移动 1 格。

军旗不能普通移动。

---

## 7. 跳跃与连跳规则

### 7.1 标准跳跃

所有可移动兵种都可以执行标准跳跃。

标准跳跃要求：

- 沿某一条棋盘直线方向。
- 起点相邻的第 1 格必须有棋子。
- 被跳过的棋子可以是友方，也可以是敌方。
- 被跳过的棋子不会因为跳跃本身被吃掉。
- 被跳过棋子后方第 1 格必须为空。
- 落点地形必须允许该棋子进入。

示意：

```text
A' A -   =>   - A A'
```

### 7.2 骑兵特殊跳跃

骑兵可以选择标准跳跃，也可以选择特殊跳跃。

特殊跳跃要求：

- 起点相邻第 1 格必须有棋子。
- 被跳过棋子后方第 1 格必须为空。
- 被跳过棋子后方第 2 格必须为空。
- 骑兵落到后方第 2 格。
- 路径中的山脉 Cell 不可通过。

示意：

```text
A' B - -   =>   - B - A'
```

### 7.3 连跳

如果一次跳跃落地后，同一个棋子从新位置仍存在合法跳跃，则可以继续跳跃。

示意：

```text
A' A - A -   =>   - A - A A'
```

连跳规则：

- 连跳必须由同一个棋子连续完成。
- 每一步都必须是合法跳跃。
- 连跳中不能穿过或落入禁止地形。
- 玩家可以在任意一次合法跳跃后主动停止。
- 吃子只在整次行动结束后统一结算，不在每一次跳跃中间结算。

## 8. “直线”的实现定义

二吃一与跳跃都依赖“直线”。在球面 Hex/Pent 棋盘上，直线不是欧式平面直线，因此实现时定义为 **沿 Cell 邻接图和邻居环顺序推进的一条或多条方向射线**。

核心原则：

- 六边形 Cell 有 6 个邻居，可以通过“对向邻居”得到唯一延长方向。
- 五边形 Cell 有 5 个邻居，本身又是大本营所在地，五个方向几何地位完全一致，**不使用几何方法强行选唯一延长线**。
- 方向射线推进到五边形 Cell 时，直线发生一次二分叉，把两个对向候选都纳入后续判定，形成一个“人”字形。

### 8.1 方向推进接口

给定相邻两个 Cell：

```text
Prev -> Cur
```

继续向前的候选 Cell 不再是单个 `Next`，而是一组分叉结果：

```text
NextCells = StepForwardBranches(Prev, Cur)
```

返回规则：

- 如果 `Cur` 是六边形，`NextCells` 最多包含 1 个 Cell。
- 如果 `Cur` 是五边形，`NextCells` 最多包含 2 个 Cell。
- 如果 `Prev` 不是 `Cur` 的有效邻居，返回空。
- 如果候选邻居为 `INDEX_NONE`，忽略该候选。

### 8.2 六边形 Cell：唯一对向邻居

六边形 Cell 的 `NeighborCellIds` 已按环形顺序排列。

若 `Prev` 是 `Cur` 的第 `x` 号邻居：

```text
Cur.NeighborCellIds[x] == Prev
```

则沿当前方向继续前进时，唯一对向邻居为：

```text
Next = Cur.NeighborCellIds[(x + 3) % 6]
```

因此：

```text
StepForwardBranches(Prev, Cur) = { Cur.NeighborCellIds[(x + 3) % 6] }
```

示意：

```text
      n5   n0(Prev)
   n4    Cur    n1
      n3(Next) n2
```

### 8.3 五边形 Cell：两个对向邻居，形成“人”字形分叉

五边形 Cell 没有严格的对边方向，不允许用几何角度选择唯一方向。

若 `Prev` 是 `Cur` 的第 `x` 号邻居：

```text
Cur.NeighborCellIds[x] == Prev
```

则两个对向候选都是合法延长方向：

```text
NextA = Cur.NeighborCellIds[(x + 2) % 5]
NextB = Cur.NeighborCellIds[(x + 3) % 5]
```

因此：

```text
StepForwardBranches(Prev, Cur) = {
    Cur.NeighborCellIds[(x + 2) % 5],
    Cur.NeighborCellIds[(x + 3) % 5]
}
```

示意：

```text
          Prev = n0
        /          \
      n4    Cur     n1
        \   /  \   /
         n3    n2
        NextB NextA
```

当方向射线走到五边形时，后续继续以 `Cur` 为新的 `Prev`，分别以 `NextA`、`NextB` 为新的 `Cur` 递归推进：

```text
Branch A: Cur -> NextA -> ...
Branch B: Cur -> NextB -> ...
```

这会把一条入射线扩展成两条后续射线，即一个“人”字形。

### 8.4 射线生成方式

攻击、跳跃、远程判定不应只依赖单个 `StepForward`，而应生成射线分支。

建议实现一个按最大长度展开的接口：

```cpp
struct FTerraRayBranch
{
    TArray<int32> CellIds;
};

void BuildForwardRayBranches(
    int32 PrevCellId,
    int32 CurCellId,
    int32 MaxStepCount,
    TArray<FTerraRayBranch>& OutBranches);
```

展开规则：

1. 当前分支末尾状态为 `(Prev, Cur)`。
2. 调用 `StepForwardBranches(Prev, Cur)` 获取 0、1 或 2 个后继。
3. 若返回 0 个，当前分支终止。
4. 若返回 1 个，将该 Cell 追加到当前分支并继续。
5. 若返回 2 个，复制当前分支为两份，分别追加两个后继，再递归推进。
6. `MaxStepCount` 用于限制最大展开长度，避免异常环路或过长扫描。

初版中各规则所需的最大长度很短：

| 用途 | 所需长度 |
| --- | --- |
| 标准跳跃 | 2 格前方 |
| 骑兵特殊跳跃 | 3 格前方 |
| 基础二吃一 | 2 格前方 |
| 弓兵远程二吃一 | 3 格前方 |
| 山脉弓兵远程二吃一 | 4 格前方 |

### 8.5 判定规则如何使用分叉线

所有依赖直线的规则，都应对每条分叉射线分别判定：

- 只要任意一条分叉射线满足跳跃条件，该跳跃目标就是合法目标。
- 只要任意一条分叉射线形成 `A A B`，就可以吃掉 `B`。
- 只要任意一条分叉射线形成 `A' A - B` 或 `A' A - - B`，弓兵远程吃子成立。
- 如果两条分叉线命中同一个目标，只记录一次。

这样可以保证五边形大本营附近不会因为缺少唯一对边而失去规则连续性，同时也不引入任意几何偏置。

## 9. 二吃一吃子规则

### 9.1 基础二吃一

基础规则来自民间棋类“二吃一”。

如果当前玩家通过本次行动，在一条直线上形成：

```text
A A B
```

则两个 `A` 吃掉 `B`。

其中：

- `B` 是敌方棋子。
- 距离 `B` 1 格的 `A` 是 **先锋**。
- 距离 `B` 2 格的 `A` 是 **真正攻击者**。
- 两个 `A` 必须属于当前行动玩家。
- 该阵型必须由本次行动形成或激活。

### 9.2 谁可以成为攻击者和先锋

| 棋子 | 可作为真正攻击者 | 可作为先锋 |
| --- | --- | --- |
| 军旗 | 可以 | 可以 |
| 步兵 | 可以 | 可以 |
| 骑兵 | 可以 | 可以 |
| 弓兵 | 可以 | 可以 |

说明：

- 军旗不能移动，但可以参与二吃一。
- 若玩家移动一个棋子，使该棋子与原地军旗形成 `A A B`，军旗可以作为其中一个 `A`。

### 9.3 “由本次行动形成或激活”

为避免棋盘上早已存在的阵型在每回合重复吃子，初版吃子只检查与 **本回合行动棋子** 相关的阵型。

行动结束后，扫描：

- 行动棋子作为真正攻击者时形成的 `A A B`。
- 行动棋子作为先锋时形成的 `A A B`。
- 行动棋子作为弓兵远程攻击者时形成的远程阵型。
- 行动棋子作为远程先锋时形成的远程阵型。

若某个敌方棋子被多个合法阵型同时命中，只移除一次。

### 9.4 同时吃子

一次行动可能形成多条合法线。

初版规则：

- 所有合法吃子目标同时结算。
- 先收集所有被吃目标，再统一移除。
- 不因移除某个棋子而立刻触发新的连锁吃子。

### 9.5 军旗被吃

如果被吃目标是军旗：

- 军旗所属阵营立即失败。
- 该阵营剩余棋子可以初版直接全部移除。
- 后续回合跳过该阵营。

## 10. 弓兵远程吃子规则

### 10.1 基础远程阵型

弓兵可以把二吃一攻击距离延长一格。

普通二吃一是：

```text
A A B
```

弓兵远程二吃一是：

```text
A' A - B
```

其中：

- `A'` 必须是当前玩家的弓兵。
- `A` 必须是当前玩家的任意棋子。
- `-` 必须为空 Cell。
- `B` 必须是敌方棋子。
- 四个 Cell 必须位于同一条方向射线上。

### 10.2 山脉弓兵远程阵型

如果弓兵 `A'` 当前位于山脉，则攻击距离再延长 1 格：

```text
A' A - - B
```

要求：

- `A'` 是山脉上的弓兵。
- `A` 是本方先锋。
- 中间两个 `-` 都必须为空 Cell。
- `B` 是敌方棋子。

### 10.3 森林防护

如果 `B` 位于森林：

- `A' A - B` 无效。
- `A' A - - B` 无效。

森林只防护弓兵远程吃子，不防护基础 `A A B`。

## 11. 胜负规则

### 11.1 失败条件

任一阵营满足以下条件即失败：

- 本阵营军旗被吃掉。

失败后：

- 该阵营不再获得回合。
- 初版建议移除该阵营所有仍在棋盘上的棋子，减少后续判定复杂度。

### 11.2 胜利条件

初版胜利条件：

- 当棋盘上只剩 1 个未失败阵营时，该阵营胜利。

可选扩展：

- 限定回合数后按存活军旗数量 / 剩余棋子数量判定。
- 占领敌方五边形基地。
- 团队模式。

这些扩展不属于初版范围。

## 12. 运行时数据结构建议

### 12.1 棋盘状态

建议新增轻量运行时状态，而不是直接实现复杂 `TechnicalDesign.md` 中的完整 `Gameplay` / `GameplaySystem` 架构。

```cpp
UENUM(BlueprintType)
enum class ETerraPieceType : uint8
{
    Flag,
    Infantry,
    Cavalry,
    Archer,
};

UENUM(BlueprintType)
enum class ETerraTerrainType : uint8
{
    Plain,
    Forest,
    Mountain,
};

USTRUCT(BlueprintType)
struct FTerraPieceState
{
    GENERATED_BODY()

    UPROPERTY() int32 PieceId = INDEX_NONE;
    UPROPERTY() int32 OwnerFactionId = INDEX_NONE;
    UPROPERTY() int32 CellId = INDEX_NONE;
    UPROPERTY() ETerraPieceType PieceType = ETerraPieceType::Infantry;
    UPROPERTY() bool bAlive = true;
};

USTRUCT(BlueprintType)
struct FTerraFactionState
{
    GENERATED_BODY()

    UPROPERTY() int32 FactionId = INDEX_NONE;
    UPROPERTY() int32 BaseCellId = INDEX_NONE;
    UPROPERTY() int32 FlagPieceId = INDEX_NONE;
    UPROPERTY() bool bAlive = true;
};
```

核心棋盘状态至少需要：

| 数据 | 作用 |
| --- | --- |
| `TArray<FTerraPieceState> Pieces` | 所有棋子 |
| `TArray<FTerraFactionState> Factions` | 12 个阵营 |
| `TMap<int32, int32> CellToPieceId` | Cell 占用表 |
| `TArray<ETerraTerrainType> CellTerrains` | 每个 Cell 的三地形类型 |
| `int32 CurrentFactionId` | 当前行动阵营 |
| `int32 TurnIndex` | 全局回合计数 |

### 12.2 服务类建议

初版可以使用纯 C++ Service，不必引入 GAS。

| 服务 | 职责 |
| --- | --- |
| `FTerraBoardInitializer` | 选择 12 个五边形并生成开局 16 子 |
| `FTerraMoveService` | 普通移动、跳跃、连跳合法性 |
| `FTerraLineService` | `StepForwardBranches` 与 `BuildForwardRayBranches` 分叉射线生成 |
| `FTerraCaptureService` | 基础二吃一与弓兵远程吃子判定 |
| `FTerraTurnService` | 回合推进、失败阵营跳过 |
| `FTerraWinService` | 军旗失败与最终胜利判定 |

## 13. 与现有交互层的对接

当前已有 hover / select Cell 高亮，因此初版交互可以按以下顺序推进：

1. 鼠标点击一个本方棋子 Cell：选中棋子。
2. 计算该棋子的合法普通移动 / 跳跃目标。
3. 用现有 `UCellHighlightComponent` 高亮可行动目标。
4. 点击目标 Cell：执行移动或一次跳跃。
5. 如果跳跃后仍有合法连跳目标：继续高亮连跳目标，允许玩家继续点选。
6. 玩家选择停止或无可连跳目标：结算吃子。
7. 高亮被吃棋子、移除棋子、更新回合。

初版可以先不做复杂 UI，只需要：

- 当前阵营提示。
- 当前选中棋子提示。
- 可移动 / 可跳跃 Cell 高亮。
- 被吃棋子短暂高亮。
- 军旗被吃后的失败提示。

## 14. 实现里程碑

### G1：棋盘状态与开局布阵

- 找到 12 个五边形 Cell。
- 每个五边形生成 16 个棋子。
- 建立 `CellToPieceId` 占用表。
- 在现有球面上可视化不同阵营棋子。

### G2：选择与普通移动

- 点击本方棋子选中。
- 高亮相邻空 Cell。
- 点击目标后移动棋子。
- 回合切换到下一个阵营。

### G3：标准跳跃与连跳

- 实现 `StepForwardBranches`。
- 选择棋子后高亮所有下一步普通行走 / 跳跃落点。
- 实现标准跳跃。
- 实现骑兵特殊跳跃。
- 实现跳跃后只能继续跳跃或点击自身结束回合的连跳交互。
- 暴露 debug 选项：回合结束后仍保持当前玩家。

### G4：基础二吃一

- 行动结束后检查 `A A B`。
- 支持军旗参与吃子。
- 支持一次行动同时吃多个目标。

### G5：弓兵远程吃子

- 实现 `A' A - B`。
- 实现山脉弓兵 `A' A - - B`。
- 实现森林防远程。

### G6：胜负闭环

- 军旗被吃即阵营失败。
- 失败阵营跳过回合。
- 只剩一个阵营时宣布胜利。

## 15. 初版规则速查

| 项目 | 规则 |
| --- | --- |
| 阵营数 | 12 |
| 基地 | 12 个五边形 Cell |
| 每阵营棋子 | 16 个 |
| 开局布局 | 中心军旗，内圈 5 弓兵，外圈 5 骑兵 + 5 步兵；阵营内初始化序号固定为军旗、弓兵、骑兵、步兵 |
| 每回合 | 移动 1 个可移动棋子 |
| 普通移动 | 相邻 1 格空 Cell |
| 标准跳跃 | 越过 1 个棋子，落到后方第 1 个空 Cell |
| 连跳 | 同一棋子可连续跳跃 |
| 骑兵 | 可落到被跳棋子后方第 2 个空 Cell；不可进山、不可越山 |
| 弓兵 | 可用 `A' A - B` 远程吃子 |
| 山脉弓兵 | 可用 `A' A - - B` 远程吃子 |
| 森林 | 保护其中目标免受弓兵远程吃子 |
| 基础吃子 | 本回合形成 `A A B`，两个 A 吃掉 B |
| 军旗 | 不动，可参与吃子，被吃则失败 |
| 胜利 | 只剩 1 个未失败阵营 |
